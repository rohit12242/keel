### Choices I made that were not specified
- **Table `"user"` kept its ERD name** (reserved word, quoted everywhere) rather
  than renaming to `app_user`. Faithful to the ERD; the cost is quoting.
- **`password_hash` is nullable.** Auth is E-06; inventing a credential now was
  off-limits, so the column exists but is empty on the seed user.
- **`from_parked_idea_id` and `created_by_review_id` are plain uuid columns with
  no FK yet** — the tables they reference (`parked_idea`, `review`) are later
  stories. FKs land with those tables.
- **Enums as real Postgres enum types** (`review_cadence`, `objective_status`,
  `schedule_mode`, `period_kind`) rather than text + CHECK.
- **Non-overlap invariant (4) enforced by an `EXCLUDE` constraint** (needs
  `btree_gist`). Contiguity ("no gaps") is *not* expressible as a cheap
  constraint and is left to the app — noted so it is not mistaken for enforced.
- **`generateSlots` implements fixed schedules only**; flexible/week generation
  throws (the seed uses a fixed segment). Flexible arrives with its story.
- **Migrations are `.cjs` raw SQL** via `pgm.sql`, not the JS builder API —
  clearer and closer to what actually runs. Migration SQL is not "repo.ts", so
  ADR-001's "SQL only in repo.ts" is not violated.

### For your review-gate answer (why local_date and logged_at are separate)
You need: the two answer different questions — `local_date` is *the day the user
meant* (a calendar date, set by the client, never moved — NFR-12 / invariant 2),
`logged_at` is *the instant the row was written* (a timestamptz, server clock).
`tz` records the zone it was logged in. An entry logged at 00:30 for the previous
evening's work must keep the previous day; deriving the day from `logged_at`
would move it. They are separate columns because one is not derivable from the
other. Evidence to point at: the three columns in `effort_entry`, and that
W3-14 takes `local_date`/`tz` from the request body, never from `now()`.
